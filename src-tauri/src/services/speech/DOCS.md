# Speech service

Recording, transcription, and the retry path that keeps a failed voice note recoverable.

## Files

| File | Role |
|------|------|
| `mod.rs` | `SpeechService` state machine (recording session, debounce, pending skill with origin + target lock, per-entry retry guard) + `SpeechError` |
| `recorder.rs` | cpal input device negotiation, WAV encoding (`hound`) |
| `transcriber.rs` | Provider calls (OpenAI / ElevenLabs), HTTP error classification, `Retry-After` parsing |
| `retry.rs` | Shared backoff loop used by both the automatic and manual paths |
| `clip_store.rs` | Short-lived WAV storage on disk, indexed by the `audio_clips` table |
| `reminder.rs` | "Still recording" nudge while a session runs |
| `widget.rs` | `RecordingWidget`: widget transitions, 50 ms level task, transport choice, position storage |

## Failure model

`SpeechError::Transcription` carries a `FailureKind`:

- **Transient** — 408, 429, 5xx, connect failures, timeouts, unparseable responses. Re-sent automatically.
- **Permanent** — 401/403, 4xx request rejections, missing API key, no speech detected. Never re-sent.

`retry.rs` runs at most `surfaces.speech_to_text.auto_retry_attempts` attempts (default 3, `1` disables retrying) with exponential backoff — 2s, 6s, 18s, capped at 60s, ±20% jitter. A numeric `Retry-After` header overrides the computed delay. Every intermediate failure emits `speech-transcription-retry`.

The HTTP timeout scales with payload size (`30s + bytes / 50 kB/s`, capped at 300s). A fixed ceiling turned slow uplinks into self-inflicted timeouts on multi-minute recordings.

## Audio clips

A recording is written to `audio_clips/<uuid>.wav` under the app data dir before the first transcription attempt, with a row in `audio_clips` (schema v6) holding the path, duration, and `expires_at`. Retention is `surfaces.speech_to_text.audio_retention_hours` (default 3, `0` disables storage entirely).

Lifecycle:

- **Success** — clip deleted immediately, unless `keep_audio_on_success` is set, in which case it is attached to the new history entry.
- **Failure** — a history entry is created with `success = false` and the clip is attached to it. This is the anchor for "Retry transcription" and "Export audio".
- **Expiry** — `spawn_audio_clip_sweeper` runs every 15 minutes (plus once at startup) and drops expired rows with their files.
- **Orphans** — the same sweep deletes any `.wav` no row points at. This is what reclaims clips lost to `ON DELETE CASCADE`, history retention pruning, and `clear()`; there is no file cleanup in the delete paths themselves.

Clips are on disk rather than in memory deliberately: a transcription usually fails because the network or the provider is down, and the user may well quit the app before trying again.

## Retry concurrency

`is_transcribing` guards the freshly recorded audio only. Manual retries use `SpeechService::begin_retry` / `end_retry`, a per-entry-id set, so replaying an hour-old clip never blocks a new recording and two retries of the same entry cannot overlap.

A manual retry **updates the history entry and the clipboard, and never pastes**. By the time someone retries, the app that had focus during dictation is long gone — pasting into whatever happens to be focused now would be worse than useless. For the same reason a retry does not re-run a pending skill, even if the original recording was started as "run skill with transcription".

Nothing is retried automatically at startup. Failed entries with a live clip wait for a click, which keeps the lifecycle free of a replay queue and avoids a burst of requests when the machine comes back online.

## Commands

| Command | Notes |
|---------|-------|
| `toggle_speech_recording` | Start/stop; on stop runs the retry loop in a background task |
| `pause_speech_recording` | Pauses the running recording; `NotRecording` error when none runs |
| `resume_speech_recording` | Resumes a paused recording |
| `cancel_speech_recording` | Discards the recording without transcribing; ignored when not recording or while transcribing |
| `retry_transcription` | Spawns a background retry; drives the UI through events, returns immediately |
| `get_audio_clip_info` | `has_audio` / `expires_at` / `duration_secs` / `is_retrying` for one entry |
| `export_audio_clip` | Copies the WAV to a caller-supplied destination (frontend picks it via `plugin-dialog`) |
| `discard_audio_clip` | Manual delete before expiry |

## Events

| Event | Payload | Emitted when |
|-------|---------|--------------|
| `speech-recording-started` | `{ action_id }` | Recording begins |
| `speech-recording-stopped` | `{ had_audio }` | Recording ends, before transcription |
| `recording-widget-state` | `{ state, level, elapsedMs }` | Every widget update (`state`: `recording`/`paused`/`processing`/`done`, `level` 0..1); sent to the `recording-widget` window only |
| `speech-transcription-retry` | `{ attempt, max_attempts, next_in_secs, reason, entry_id }` | Each transient failure; `attempt: 0` marks the start of a manual retry |
| `speech-transcription-complete` | `{ text, duration_secs, entry_id }` | Success (or a discarded too-short recording) |
| `speech-transcription-error` | `{ message, recoverable, entry_id, has_audio, attempts }` | Attempts exhausted or a permanent failure |

Cancel emits `speech-recording-stopped` and then `speech-transcription-complete` with empty `text`, like a discarded too-short recording.

`entry_id` is `null` for the automatic path when no history entry was created (pending-skill executions, no-speech results).

## Recording widget

`widget.rs` (`RecordingWidget`) is called from `commands/speech.rs` at every transition, so one place owns widget state and the setting check. Setting: `surfaces.speech_to_text.show_recording_widget`, default `true`; off keeps the toast-only behavior.

`surfaces.speech_to_text.monochromatic_widget_icon`, default `true`: the "Copied" check of the `done` state uses the widget foreground (`#e5e5e7`); off draws it green (`#62A878`). Read in `show()` with `show_recording_widget`, so a change applies from the next recording. GNOME: 4th argument of `ShowRecordingWidget`, the extension picks `icons/recording-check-mono.svg` or `icons/recording-check.svg`. X11/macOS: `monochromatic` field of every `recording-widget-state` payload.

- **Transports** — GNOME Wayland: the extension draws the widget (`ShowRecordingWidget` / `UpdateRecordingWidget` / `HideRecordingWidget`, see [linux-wayland-gnome-extension.md](../../../../docs/gotchas/linux-wayland-gnome-extension.md)). X11 and macOS: webview window `recording-widget` (`src/windows/recording-widget/`) fed by `recording-widget-state`. Any other Wayland session, or a failed `ShowRecordingWidget`, falls back to toasts for that recording with a `warn` log. On macOS the `recording-widget` window is re-classed at setup into the non-activating `NSPanel` subclass `PromptheusWidgetPanel` (`canBecomeKeyWindow`/`canBecomeMainWindow` NO, `hidesOnDeactivate` NO, `services/macos_panel.rs`), because a click on a plain `NSWindow` of an inactive app activates the app and the frontmost app stops receiving keystrokes; it is shown and hidden with tauri `show()`/`hide()`, never `show_panel_without_activating`.
- **Toasts** — while the widget is shown it replaces "Recording started", "Processing audio" and "Speech transcribed". Error and warning toasts and the reminder stay.
- **Transitions** — `recording` ⇄ `paused` → `processing` → `done` (about 1 s, "Copied"), then closed. `processing` shows only a dimmed wave of 3 px bars across the inner width of the pill, travelling left to right once per 1.2 s: no buttons, no timer, no label. GNOME: 35 bars driven by one `GLib.timeout_add` (33 ms), opacity 150. X11/macOS: 35 bars with a staggered CSS `@keyframes` `scaleY` animation, color `#929294` instead of opacity (see [linux-webkit-opacity.md](../../../../docs/gotchas/linux-webkit-opacity.md)). Closed without `done`: start failure (never shown), too-short recording, encode or runtime/API-key error, transcription error, cancel, no speech detected. A pending skill closes the widget right after processing, with no `done`.
- **Pause** — `is_recording` stays `true`; the cpal callback drops samples while paused and the microphone stays open (the OS indicator stays on); `SpeechService::elapsed()` excludes paused time; the reminder skips paused ticks and shifts its timers by the pause length. Stop from pause transcribes.
- **Level** — a session-scoped task every 50 ms computes the RMS of the new buffer tail (`reminder::rms`) and sends a level on a dB scale with state and elapsed time, awaiting each update before the next tick. `level_from_rms`: `dbfs = 20·log10(rms / 32768)`, level = `clamp((dbfs − FLOOR_DB) / (CEIL_DB − FLOOR_DB), 0, 1)` with `FLOOR_DB = −50`, `CEIL_DB = −20` (RMS ≈ 104 → 0, ≈ 1036 → 0.67, ≥ 3277 → 1). A linear `rms / 6000` kept normal speech (RMS 500–3000) at 0.1–0.4, so the bars looked flat. The mapped level then goes through `smooth_level`, an envelope follower stepped once per tick: `level += (target − level) · rate` with `LEVEL_ATTACK = 0.6` when the target is higher and `LEVEL_RELEASE = 0.2` when it is lower, so a rise reaches 60 % of the step in 50 ms and a fall from 1 to silence takes about 11 ticks (550 ms) to drop below 0.1. The smoothed value starts at 0 per session and is reset to 0 while paused. Rendering interpolates between the 20 Hz updates: GNOME calls Clutter `ease` on each bar's `scale_y` (a transform: sub-pixel, no relayout) with a 60 ms `LINEAR` ease, about one update interval, so successive segments join at a near-constant speed; the earlier 100 ms `EASE_OUT_QUAD` on `height` restarted at its highest speed every 50 ms and rounded to whole pixels, which showed as a slight tremor. Clutter computes the intermediate frames on the frame clock and JS runs only on the 20 Hz updates (see [linux-wayland-gnome-extension.md](../../../../docs/gotchas/linux-wayland-gnome-extension.md)); X11/macOS bars are `transform: scaleY(…)` with `transition: transform 120ms ease-out`.
- **Position** — `ui_state.json` keys `recording_widget.shell_position` (logical stage pixels) and `recording_widget.window_position` (physical pixels); `{ x, y }`. Separate keys so a session switch never reuses coordinates in the wrong space. Setting `surfaces.speech_to_text.recording_widget_at_cursor` (default `true`): the pill opens with its top-left corner at the cursor, moved by `monitor::clamp_origin` (the same clamp as the context menu, `clamp_menu_origin`) so it lies fully inside the work area of the cursor's monitor. macOS: `app.cursor_position()` + `find_monitor_at`, the window is sized to `PILL_WIDTH`×`PILL_HEIGHT` times the monitor scale first. GNOME: `GetPointer` and its work area, passed to `ShowRecordingWidget` with `has_position = true`; the extension does not clamp. With the setting on a drag is not stored (`should_store_drag`); off: the stored position, else the default (bottom center of the work area under the pointer, 24 px above the bottom edge). `RecordingWidget` keeps the current origin and the work area of its monitor (`Placement`, physical px for the window, logical stage px for the shell), set on show and on every drag.
- **Pill model** — the backend owns what the pill shows and pushes one snapshot per change (on show, selection, lock, context change, size change). Fields: `targets` (`__dictation__`/`Dictation` first, then every skill offered in `pill` in `list_skills()` order), `selectedId`, `selectedLabel` (no pending skill → `__dictation__`/`Dictation`; a pending skill → its id and name even when not in `targets`, e.g. a Shift+click `__chat__` → "Chat"), `targetLocked`, `items` (`index`, `kind` `text`|`image`, `label` `Text #n`/`Image #n` per kind in context order, `preview`: the first 300 chars of a text item plus `…` when longer via `text_preview`, empty for images), `itemRows` (0–3, see Size), `contextVersion`, `dropdownUp` (window transport only; `dropdown_opens_up` from the pill's current origin, recomputed on every snapshot; drives the chevron only; it can be stale after a user drag until the next snapshot, as on the GNOME pill), `x`, `y` (origin: physical px for the window, logical stage px for the shell). Transports: GNOME `UpdateRecordingWidgetModel(a(ss), s, s, b, a(ussss), u, t, i, i)` (items are `index, kind, label, preview, image_path`; `image_path` is the absolute preview file of an image item, empty for text or when writing failed; the `u` after `items` is `itemRows`); X11/macOS event `recording-widget-model` with the same fields in camelCase (`targets` as `{id, label}`, `items` as `{index, kind, label, preview}`, no image path and no image data). Pure builders in `widget.rs`: `pill_targets`, `pill_items`, `text_preview`, `item_rows`, `build_model`, `pill_size`, `regrow_origin`.
- **Preview files** — GNOME only (the webview gets no image data). `services/speech/pill_previews.rs` writes one PNG per image item into `app_cache_dir()/pill-previews/`, named `<16 hex digits of a DefaultHasher hash of the base64 string>.png` (same data, same file; an existing file is not rewritten). A PNG source is decoded and saved as a thumbnail fitting 480 × 320 keeping the aspect, never upscaled; any other media type is written as is. `push_model` runs `sync_previews` in `spawn_blocking`: writes the missing files, deletes every file in the dir not in the current set, and the paths go into the model as `image_path`; a failure logs `warn` (path and error, never data) and the items get an empty path. Closing a shell pill runs `clear_previews` in `spawn_blocking`.
- **Size** — `PILL_WIDTH` 240 × (`PILL_HEIGHT` 80 (two rows) + `items_height(rows)`) (`pill_size(rows)`). `item_rows(labels, locked)` wraps chips greedily (width `28 + 7 × label chars` plus 16 for the × unless locked, gap 4) into lines of 212 and returns the line count capped at `MAX_ITEM_ROWS` 3 (no items → 0). `items_height`: 0 for 0 rows, else `rows × 22 + (rows − 1) × 4 + 10` (1 → 32, 2 → 58, 3 → 84). `refresh_model` gathers the model, and on every row change (`rows_resize`), including the lock that removes the × width, `resize_locked` runs: `regrow_origin` keeps the bottom edge and clamps into the work area; the window gets the new size and position in one `apply_frame` (recorded as `programmatic_origin`; an open dropdown is closed by the same call, not by a second frame), the shell gets the origin in the snapshot.
- **macOS layout and dropdown** — `src/windows/recording-widget/App.svelte` renders the same two-row pill as the GNOME extension (width 240, rows 40 + 40, items row 32 on top only with items, radius 16; constants equal `widget.rs` and `extension.js`): row 1 bars/time/pause/stop/cancel (`processing` wave, `done` "Copied"), row 2 target button (label, `ChevronDown`/`ChevronUp`), Paste, stop + chat; after the lock or in `done` only the label; chips collapse into `+N` by the same width estimate as the extension. Before the first `recording-widget-model` the label is `Dictation`. The panel never becomes key, so every button has `tabindex="-1"` and there is no hover state.
- **Overlay slot (dropdown and preview)** — one slot `inner.overlay: Option<Overlay { kind: Dropdown|Preview, up, height }>` (physical px) holds at most one overlay; pure `next_overlay(current, request)` returns the new overlay and the kind it closed: opening one kind replaces the other and reports it closed, closing a kind that is not current changes nothing. Replacing applies the new grown frame in one `apply_frame`, never a close frame then an open frame. Commands: `set_recording_widget_dropdown(open, rows)` and `set_recording_widget_preview(open)` (window transport only, error otherwise), both return `"up"`/`"down"`. The preview height is `PREVIEW_FRAME_HEIGHT` 166 (popover max height 160 + gap 6) × scale. While the preview shows, the transparent strip of the grown frame takes clicks (accepted). Dropdown: click-only HTML list (no outside-click close, no keyboard). Command `set_recording_widget_dropdown(open, rows)` returns `"up"` or `"down"`; the page renders the list on the returned side, so it always matches the applied frame. `dropdown_opens_up`: pill centre in the lower half of the work area → up. `grown_frame`: up keeps the bottom edge (origin y minus list height), down keeps the top edge, then `clamp_origin` with the grown size; list height = (`rows` × 28 + 2 × 4) × scale (`DROPDOWN_ROW_HEIGHT`, `DROPDOWN_PADDING`). The frame is applied by `macos_panel::set_frame_physical`: one `setFrame:display:` on the main thread (`run_on_main_thread`) instead of `set_size` + `set_position`, which would draw an intermediate frame (flicker); Tauri's top-left physical px are converted to points with a bottom-left origin from the primary monitor height. The new origin goes into `programmatic_origin`, so the resulting `Moved` is not stored as a drag. Other platforms fall back to `set_size` + `set_position`. Closing (command with `open: false`) restores the pill frame from `Placement` re-clamped. The page closes the list on selection (after `select_recording_widget_target`), a second click on the button, a locked target or `done`. The backend closes either overlay and emits `recording-widget-dropdown-closed` to the window on a user drag (the pill is restored at the dragged position, shifted by the list height when it opened up, and that position is stored), on a pill size change and on hide.
- **Pointer on macOS** — WebKit tracks the mouse only in the key window and the widget panel never becomes key, so the page gets no hover events. `macos_panel::install_pointer_tracking` (called once from `setup/windows.rs` after `make_nonactivating_widget_panel`) adds one `NSTrackingArea` on the content view with `NSTrackingActiveAlways | NSTrackingMouseMoved | NSTrackingMouseEnteredAndExited | NSTrackingInVisibleRect` (follows frame changes); its owner is an `NSObject` subclass `PromptheusPointerOwner` leaked for the app lifetime (the area does not retain its owner). `mouseMoved:`/`mouseEntered:` emit `recording-widget-pointer` `{ x, y }` to `recording-widget` in points (= CSS px) with a top-left origin (`top_left_y`: `bounds height − y` unless the view `isFlipped`); `mouseExited:` emits `null`.
- **Target and lock** — `SpeechService` holds one pending slot (`PendingPrompt { id, name, origin }`, origin `ShiftClick` or `Pill`) and `target_locked`. `start_recording` calls `reset_target_for_start`: the slot survives only when its origin is `ShiftClick` and its id equals the start's `action_id`; the lock is cleared. `select_target` and `request_stop_chat` are rejected (`TargetLocked`) after `take_pending_prompt`, which takes the slot, returns the stop + chat flag and sets the lock in one step (after transcription). The flag is cleared by `reset_target_for_start`. Selecting `__dictation__` clears the slot.
- **Intents** — select target, remove item (carries `contextVersion`; stale version removes nothing), Paste. GNOME: `RecordingWidgetAction` `paste`, signals `RecordingWidgetTargetSelected(s)` and `RecordingWidgetItemRemoved(u, t)`. Webview: commands `select_recording_widget_target(id)`, `remove_recording_widget_item(index, contextVersion)`, `paste_into_recording_widget()`. All run the same async functions in `commands/speech.rs`; each is ignored (debug log) when the pill is not shown, and an unknown target id is ignored. Stop + chat: GNOME `RecordingWidgetAction` `stop_chat`, webview command `stop_chat_speech_recording()`; recording or paused → set the flag, then the normal stop; processing → only set the flag (rejected after the lock). Paste (`commands/context.rs`): `paste_kind` — file list → nothing, else image, else text; reads the clipboard off the async runtime, appends to `ContextManagerService`, emits `context-changed`. Files are not pasted.
- **Pill skill run** — in the transcription task of `toggle_speech_recording`, origin `ShiftClick` keeps the old path (pill closed at once, `speech-alternative-execute`). Origin `Pill` keeps the pill in `processing` and runs `run_skill_stream` in the backend (`run_pill_skill`): no-op `Channel`, transcript as `input_override`, source `pill`, route `clipboard_chat` when the stop + chat flag is set else `clipboard`, `notify_success = false` (the pill's "Copied" replaces the success toast; the executor shows the error toast for prepare and stream errors). Success → `done`; with the flag, the chat opens with the entry id (`open_conversation_dialog`, source `pill`). Error, cancelled run and empty transcript → pill closed (empty transcript also shows a "No speech detected" error toast). `is_transcribing` stays set until the run ends. Plain dictation with the flag: after the clipboard write and `done`, the chat opens with the transcript, `auto_send_input`, source `pill`.
- **Generation guard** — the widget generation is captured when the recording stops; `done_if_current` / `close_if_current` act only when the pill is shown and `generation` is unchanged (`Inner::is_current`), so a run that ends late never touches a newer recording's pill.
