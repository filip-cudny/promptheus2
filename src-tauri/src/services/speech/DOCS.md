# Speech service

Recording, transcription, and the retry path that keeps a failed voice note recoverable.

## Failure model

`SpeechError::Transcription` carries a `FailureKind`:

- **Transient** — 408, 429, 5xx, connect failures, timeouts, unparseable responses. Re-sent automatically.
- **Permanent** — 401/403, 4xx request rejections, missing API key, no speech detected. Never re-sent.

`retry.rs` runs at most `surfaces.speech_to_text.auto_retry_attempts` attempts (default 3, `1` disables retrying) with exponential backoff — 2s, 6s, 18s, capped at 60s, ±20% jitter. A numeric `Retry-After` header overrides the computed delay. Every intermediate failure emits `speech-transcription-retry`.

The HTTP timeout scales with payload size (`30s + bytes / 50 kB/s`, capped at 300s). A fixed ceiling turned slow uplinks into self-inflicted timeouts on multi-minute recordings.

## Audio clips

A recording is written to `audio_clips/<uuid>.wav` under the app data dir before the first transcription attempt, with a row in `audio_clips` (schema v6) holding the path, duration, and `expires_at`. Retention is `surfaces.speech_to_text.audio_retention_hours` (default 3, `0` disables storage entirely).

Lifecycle:

- **Success** — clip deleted immediately, unless `keep_audio_on_success` is set, in which case it is attached to the new history entry.
- **Failure** — a history entry is created with `success = false` and the clip is attached to it. This is the anchor for "Retry transcription" and "Export audio".
- **Expiry** — `spawn_audio_clip_sweeper` runs every 15 minutes (plus once at startup) and drops expired rows with their files.
- **Orphans** — the same sweep deletes any `.wav` no row points at. This is what reclaims clips lost to `ON DELETE CASCADE`, history retention pruning, and `clear()`; there is no file cleanup in the delete paths themselves.

Clips are on disk rather than in memory deliberately: a transcription usually fails because the network or the provider is down, and the user may well quit the app before trying again.

## Retry concurrency

`is_transcribing` guards the freshly recorded audio only. Manual retries use `SpeechService::begin_retry` / `end_retry`, a per-entry-id set, so replaying an hour-old clip never blocks a new recording and two retries of the same entry cannot overlap.

A manual retry **updates the history entry and the clipboard, and never pastes**. By the time someone retries, the app that had focus during dictation is long gone — pasting into whatever happens to be focused now would be worse than useless. For the same reason a retry does not re-run a pending skill, even if the original recording was started as "run skill with transcription".

Nothing is retried automatically at startup. Failed entries with a live clip wait for a click, which keeps the lifecycle free of a replay queue and avoids a burst of requests when the machine comes back online.

## Commands

The recording commands live in `commands/speech.rs`. `toggle_speech_recording` starts and stops (on stop it runs the retry loop in a background task); `cancel_speech_recording` is ignored when not recording or while transcribing; `retry_transcription` spawns a background retry, drives the UI through events and returns immediately; `export_audio_clip` copies the WAV to a caller-supplied destination (the frontend picks it via `plugin-dialog`); `discard_audio_clip` deletes a clip before expiry. `get_audio_clip_info` returns `has_audio`, `expires_at`, `duration_secs`, `bytes` and `is_retrying` for one entry.

## Events

| Event | Payload | Emitted when |
|-------|---------|--------------|
| `speech-recording-started` | `{ action_id }` | Recording begins |
| `speech-recording-stopped` | `{ had_audio }` | Recording ends, before transcription |
| `recording-widget-state` | `{ state, level, elapsedMs, monochromatic }` | Every widget update (`state`: `recording`/`paused`/`processing`/`done`, `level` 0..1); sent to the `recording-widget` window only |
| `speech-transcription-retry` | `{ attempt, max_attempts, next_in_secs, reason, entry_id }` | Each transient failure; `attempt: 0` marks the start of a manual retry |
| `speech-transcription-complete` | `{ text, duration_secs, entry_id }` | Success (or a discarded too-short recording) |
| `speech-transcription-error` | `{ message, recoverable, entry_id, has_audio, attempts }` | Attempts exhausted or a permanent failure |

Cancel emits `speech-recording-stopped` and then `speech-transcription-complete` with empty `text`, like a discarded too-short recording.

`entry_id` is `null` for the automatic path when no history entry was created (pending-skill executions, no-speech results).

## Recording widget

Convention: the window pill (`src/windows/recording-widget/App.svelte`) and the GNOME Shell extension pill (`linux/gnome-shell-extension/promptheus@promptheus.desktop/extension.js`) look and behave the same (width, button order, icons, colours, gaps, hover, animations). A change to one pill's look or behaviour is made to both in the same change; only platform-forced differences are allowed and are listed under "macOS layout and dropdown".

`widget.rs` (`RecordingWidget`) is called from `commands/speech.rs` at every transition, so one place owns widget state and the setting check. Setting: `surfaces.speech_to_text.show_recording_widget`, default `true`; off keeps the toast-only behavior.

`surfaces.speech_to_text.monochromatic_widget_icon`, default `true`: the "Copied" check of the `done` state uses the widget foreground (`#e5e5e7`); off draws it green (`#62A878`). Read in `show()` with `show_recording_widget`, so a change applies from the next recording. GNOME: 4th argument of `ShowRecordingWidget`, the extension picks `icons/recording-check-mono.svg` or `icons/recording-check.svg`. X11/macOS: `monochromatic` field of every `recording-widget-state` payload.

- **Transports** — GNOME Wayland: the extension draws the widget (`ShowRecordingWidget` / `UpdateRecordingWidget` / `HideRecordingWidget`, see [linux-wayland-gnome-extension.md](../../../../docs/gotchas/linux-wayland-gnome-extension.md)). X11 and macOS: webview window `recording-widget` (`src/windows/recording-widget/`) fed by `recording-widget-state`. Any other Wayland session, or a failed `ShowRecordingWidget`, falls back to toasts for that recording with a `warn` log. On macOS the `recording-widget` window is re-classed at setup into the non-activating `NSPanel` subclass `PromptheusWidgetPanel` (`canBecomeKeyWindow`/`canBecomeMainWindow` NO, `hidesOnDeactivate` NO, `services/macos_panel.rs`), because a click on a plain `NSWindow` of an inactive app activates the app and the frontmost app stops receiving keystrokes; it is shown and hidden with tauri `show()`/`hide()`, never `show_panel_without_activating`.
- **Toasts** — while the widget is shown it replaces "Recording started", "Processing audio" and "Speech transcribed". Error and warning toasts and the reminder stay.
- **Transitions** — `recording` ⇄ `paused` → `processing` → `done` (about 1 s, "Copied"), then closed. `processing` shows only a dimmed wave of 2 px bars with 3 px gaps (the level meter's gap) across the inner width of the pill, travelling left to right once per 1.2 s: no buttons, no timer, no label. Bar count on both pills `floor((width − 2 × 14 + gap) / (bar + gap))` = 47. GNOME: driven by one `GLib.timeout_add` (33 ms), opacity 150. X11/macOS: a staggered CSS `@keyframes` `scaleY` animation, color `#929294` instead of opacity (see [linux-webkit-opacity.md](../../../../docs/gotchas/linux-webkit-opacity.md)). Closed without `done`: start failure (never shown), too-short recording, encode or runtime/API-key error, transcription error, cancel, no speech detected. A pending skill closes the widget right after processing, with no `done`. The `done` row-1 content (check + "Copied") enters once with scale 0.85 → 1 and opacity 0 → 1, 180 ms, ease-out cubic, pivot at the centre; webview: CSS `@keyframes`, off under `prefers-reduced-motion: reduce`; GNOME: `ease` with `EASE_OUT_CUBIC` after the content is added to row 1.
- **Pause** — `is_recording` stays `true`; the cpal callback drops samples while paused and the microphone stays open (the OS indicator stays on); `SpeechService::elapsed()` excludes paused time; the reminder skips paused ticks and shifts its timers by the pause length. Stop from pause transcribes. In `paused` the meter bars hold the last level and are dimmed.
- **Level** — a session-scoped task every 50 ms computes the RMS of the new buffer tail (`reminder::rms`) and sends a level on a dB scale with state and elapsed time, awaiting each update before the next tick. `level_from_rms`: `dbfs = 20·log10(rms / 32768)`, level = `clamp((dbfs − FLOOR_DB) / (CEIL_DB − FLOOR_DB), 0, 1)` with `FLOOR_DB = −50`, `CEIL_DB = −20` (RMS ≈ 104 → 0, ≈ 1036 → 0.67, ≥ 3277 → 1). A linear `rms / 6000` kept normal speech (RMS 500–3000) at 0.1–0.4, so the bars looked flat. The mapped level then goes through `smooth_level`, an envelope follower stepped once per tick: `level += (target − level) · rate` with `LEVEL_ATTACK = 0.6` when the target is higher and `LEVEL_RELEASE = 0.2` when it is lower, so a rise reaches 60 % of the step in 50 ms and a fall from 1 to silence takes about 11 ticks (550 ms) to drop below 0.1. The smoothed value starts at 0 per session and is reset to 0 while paused. Rendering interpolates between the 20 Hz updates: GNOME calls Clutter `ease` on each bar's `scale_y` (a transform: sub-pixel, no relayout) with a 60 ms `LINEAR` ease, about one update interval, so successive segments join at a near-constant speed; the earlier 100 ms `EASE_OUT_QUAD` on `height` restarted at its highest speed every 50 ms and rounded to whole pixels, which showed as a slight tremor. Clutter computes the intermediate frames on the frame clock and JS runs only on the 20 Hz updates (see [linux-wayland-gnome-extension.md](../../../../docs/gotchas/linux-wayland-gnome-extension.md)); X11/macOS bars are `transform: scaleY(…)` with `transition: transform 120ms ease-out`.
- **Position** — `ui_state.json` keys `recording_widget.shell_position` (logical stage pixels) and `recording_widget.window_position` (physical pixels); `{ x, y }`. Separate keys so a session switch never reuses coordinates in the wrong space. Setting `surfaces.speech_to_text.recording_widget_at_cursor` (default `true`) with `recording_widget_anchor` (`PillAnchor`, default `above_right`): the pill opens on the side of the cursor the anchor names. `above_*` puts the bottom edge at the cursor, `below_*` the top edge; `*_right` puts the left edge at the cursor, `*_center` centers the pill on it, `*_left` puts the right edge at it. `anchored_origin` computes that origin and then `monitor::clamp_origin` (the same clamp as the context menu, `clamp_menu_origin`) moves it fully inside the work area of the cursor's monitor; there is no flip, so near an edge the pill may cover the cursor. Logical stage px on GNOME, physical px from the physical size (`physical_size(pill_size(rows), scale)`) on macOS. macOS: `app.cursor_position()` + `find_monitor_at`, the window is sized to `pill_size(rows)` times the monitor scale and positioned first, and shown only after the new recording's state and model are pushed (the page keeps the previous run's last frame across hides). GNOME: `GetPointer` and its work area, passed to `ShowRecordingWidget` with `has_position = true`; the extension does not clamp. - **Pill skill run** — in the transcription task of `toggle_speech_recording`, `transcript_plan` picks the path from the pending target, the stop + chat flag and the transcript. Origin `ShiftClick` keeps the old path (pill closed at once, `speech-alternative-execute`, flag ignored). Origin `Pill` without the flag keeps the pill in `processing` and runs `run_skill_stream` in the backend (`run_pill_skill`): no-op `Channel`, transcript as `input_override`, source `pill`, route `clipboard`, `notify_success = false` (the pill's "Copied" replaces the success toast; the executor shows the error toast for prepare and stream errors). - **Stop + chat (`Chat` plan)** — with the flag the backend runs no skill and writes no clipboard: it adds the speech history entry (as dictation does, so the audio clip and `speech-transcription-complete` work the same), closes the pill (no `done`, no toast), snapshots the clipboard (`ClipboardService::fingerprint`, off the async runtime), stores it as a pending copy and opens the chat (`open_conversation_dialog`, source `pill`, `auto_send_input`, transcript as initial input, `copy_token`). The skill id is the pill target's (the chat runs that skill with the skill's `model`), empty for plain dictation. The chat's frontend calls `copy_chat_answer_if_unchanged(token, text)` after the first answer; the answer is copied only if the clipboard still matches the snapshot.

One new tab per run. A tab with an armed message is never unloaded by the live limit or the 30 min pass; if it is unloaded anyway (window hidden), its message goes to `fallback` at once. The pending message (`AiWebviewState::arm_message`) is delivered once, on the next `PageLoadEvent::Finished` whose host equals the provider URL host (`take_delivery`), by evaluating `delivery_script`. The page script `__deliverMessage` polls 15 s for the single selector `.ProseMirror[contenteditable="true"]`. `fetch` and `XMLHttpRequest.prototype.send` wrappers, installed once per document, count requests whose body is a `Blob`/`File` or a `FormData` with `Blob` entries (one per entry; not strings, `ArrayBuffer`, typed arrays or `keepalive`); a `fetch` leaves the count when its promise settles, an XHR on `loadend`. With images: arm the counter → paste images → wait (every 100 ms) until counted images ≥ image count, none in flight and 1 s with no new counted request → disarm → paste text → synthetic Enter keydown every 500 ms until `location.pathname` matches `^/(chat|c)/` (sent) or 30 s pass (typed); no done within 20 s → text pasted, no Enter, `typed`. Text-only runs skip the wait. It reports through router kind `webview_send_outcome` (`status=sent|typed|no_composer`, `run`, optional `uploads` and `waitedMs`; no text). Failure (outcome `typed`/`no_composer`, any surface or tab activation error, a replaced message, or no outcome within the 80 s deadline) → `fallback`: transcript to the clipboard inside `spawn_blocking` (never on the GTK main thread) and an always-shown error toast `Not sent to <provider>`. Reasons: synthetic Enter over a send button (localized labels, claude.ai's Enter handler sends during a running upload, so the script waits for the upload requests); the path check over "composer empty" (claude.ai turns a long paste into an attachment, so the composer can stay empty after a failed send).
- **Webview plan** — a pending target whose id gives `webview_provider_of(id)` (prefix `WEBVIEW_TARGET_PREFIX` `webview:`, built by `webview_target_id`; a skill name can never contain `:`) plans `TranscriptPlan::Webview { provider_id }` for stop and stop + chat alike, after the `ShiftClick` and empty-transcript checks (empty → `NoSpeech`). The route adds the speech history entry, `close_if_current`, then `send_to_provider_chat`; no clipboard snapshot, no `done`, no toast (failures are handled in the delivery). Selection and lock work as for skills (`select_target`, `shown_target` shows the provider name).
- **Generation guard** — the widget generation is captured when the recording stops; `done_if_current` / `close_if_current` act only when the pill is shown and `generation` is unchanged (`Inner::is_current`), so a run that ends late never touches a newer recording's pill.
