# Settings UI

Settings dialog window — sidebar navigation + per-section content. Lives in its own Tauri window (`settings-dialog` label, entry `settings-dialog.html` → `src/windows/settings-dialog/App.svelte`).

This doc captures the patterns applied here so new sections stay consistent.

Files whose role does not follow from the name: `SettingsSidebar.svelte` exports the `SettingsSection` union and `SIDEBAR_GROUPS`; `SettingsContent.svelte` routes `activeSection` to a `Section*` component; `SettingsSection.svelte` is the shared section shell, not a section; `SettingField.svelte` is the label + description + error wrapper for every catalog-bound control.

The root is `src/windows/settings-dialog/App.svelte` (calls `store.init()` / `store.destroy()`); state lives in the single rune store `getSettingsStore()` (`$lib/stores/settings.svelte.ts`), which subscribes to the backend `settings-changed` event.

## Conventions

### General section

`SectionGeneral.svelte` holds five fields, each through `SettingField`: "Theme" (button toggling light/dark, labelled "Switch to light mode" / "Switch to dark mode" with `Sun` / `Moon`), "Logo" and "Icons" (each a `SelectDropdown` of Color / Mono, saved with `updateSetting("appearance", { ...current, <field>: value })`), "Launch at startup" and "Show tray icon" (checkboxes saved with `updateSetting(<key>, value)`). The tray icon applies after restart; `SettingField` shows that from its catalog entry.

`SectionSpeech.svelte` holds two selects for the Claude pill delivery, "Claude target" (`claude_target`: webview or Claude Desktop) and "Stop + chat target" (`stop_chat_target`: Chat or Claude); each saves its own field with `updateSpeechToTextConfig`.

### Model creation dialog

"+ model" in `ModelList` opens `CreateModelDialog.svelte` (pattern of `CreateSkillDialog`) with the type preset; nothing is written until the dialog's Create. Fields: Type, Display name, Provider, Model, API key (`EnvVarPicker`, no literal input), optional Base URL. `newModelErrors` (`$lib/utils/newModel.ts`) mirrors the backend `validate` rules; Create is disabled while it returns errors, and an error shows at its field once the field was blurred (the API key: once a value was picked). A backend rejection shows at the field (`store.fieldError("models[<id>].<field>")`, the id is generated once per dialog) and keeps the dialog open; success closes it and selects the new model. A "New…" in the API key picker writes the variable to the list (and its value) at once, before Create; only the model waits for Create.

### Store toggle

`ModelEditor` hides "Store" when `draft.api_mode === "completions"`: the flag has no effect on Chat Completions. The stored value is kept, so switching back to Responses shows it unchanged.

### Models section — Assignments

`ModelList` pins an "Assignments" row (lucide `ArrowLeftRight`) above the groups and the empty state; it is always shown. `SectionModels` selects either Assignments (`selectedId === null`, the default on first open and after a delete) or a model id; an id that is no longer in `store.models` falls back to Assignments, and a `navigateTo` key naming a model (`models[<id>]…`) still selects that model. The editor pane shows `ModelAssignments` for Assignments, else `ModelEditor`. `SectionModels` calls `getSkillsStore().init()` on mount (idempotent), so skill pins are known when Settings opens straight into Models.

`ModelAssignments` has three cards: "Text features" (Chat, Quick actions, Title generation, Settings agent: model select, reasoning effort select, "Open in <section> ›"), "Speech" (Speech to text, STT model select) and "Pinned in skills" (rendered only when a skill in `getSkillsStore().full` has a non-empty `model`; read-only rows with the model name or the stored id, link "Open skill ›" → `navigateTo("skills[<name>]")`). Each surface row has the element id `assignment-<surface>`. Model selects write like the sections do (`updateSurfaceModel`, `setSpeechToTextModel`); the empty option is "Not set" for Chat and Speech, `sameAsChatLabel` for the others. The effort select of Chat, Quick actions and Settings agent takes its options from the capabilities of the effective model (`chat` id, `quickActionsModelId`, `agentModelId`); Title generation and Speech have no effort cell.

Narrow pane: `.model-assignments` is a size container; at a content width of at most 600 px (`@container`) the tables stack: each row a wrapping flex row, the feature on its own line, then the model select, the effort select with a "Reasoning effort" caption (`data-label` + `::before`, standing in for the hidden `thead`) and the link; empty cells are hidden with `td:empty` (an `{#if}` leaves only a comment anchor, which `:empty` ignores). Select labels ellipsize (`td :global(.trigger .label)`), so a long model name cannot widen the table past the pane at any width. A four-column table does not fit the narrowest pane (300 px at the 800 px window minimum with the panel hidden, 342 px with it docked).

"Open in" calls `navigateTo` with `surfaces.chat.generation.model_id` (Chat), `surfaces.quick_actions.generation.model_id` (Context menu), `surfaces.title_generation.generation.model_id` and `surfaces.settings_agent.generation.model_id` (Chat), `surfaces.speech_to_text.model_id` (Speech). The view uses no `SettingField`: `navigateTo` finds a field by `setting-<catalog path>`, which must stay unique to the field's own section.

`SURFACE_LABELS` (`$lib/constants/surfaces`) is sentence case (`Chat`, `Quick actions`, …): these are the row labels here and the texts of the surface tags (`modelUseLabel`).

### Tests of pure modules

Pure TS modules (no Svelte runes, no `$lib` imports other than `import type`) live in `src/lib/utils`. Their tests are `tests/*.test.mjs` (`node:test`, `node:assert`), importing the `.ts` file directly through Node type stripping; run `node --test "tests/*.test.mjs"` from the root. There is no test runner dependency; `node --test tests/` does not work on Node 25, which treats the directory as a module.

### Sidebar groups and adding a section

`SIDEBAR_GROUPS` in `SettingsSidebar.svelte` lists three groups, each an ordered array of items: "App" (General, Notifications, History, Sync, Environment), "AI" (Models, Prompt Base, Skills, MCP Servers), "Features" (Chat, Context menu, Speech). There is no disabled item; a section appears in the sidebar only once it renders.

Active item is marked with a 2px left border in `--accent`, never a filled background, so the accent only signals "you are here" (the same single-accent rule as the conversation window: blue ≡ user/marker, never decoration).

1. Add the id to the `SettingsSection` union and an item to a group's array in `SettingsSidebar.svelte`.
2. Create `Section<Name>.svelte` here and branch on it in `SettingsContent.svelte`'s `{#if activeSection === ...}`.
3. Read state from `getSettingsStore()` — never `invoke("get_settings")` from a component.
4. Write through `$lib/services/settings.ts` helpers; the store auto-refreshes on the backend's `settings-changed` event.

### SettingField

Every control bound to a settings key is wrapped in `<SettingField key="<catalog path>">` (`itemId` for list items). It takes label and description from the catalog entry (`getSettingsCatalogStore()` in `$lib/stores/settingsCatalog.svelte.ts`, loaded once per window), marks `after_restart` entries, renders the backend field error whose concrete key maps to `key`, and sets `id="setting-<key>"`. A new key needs a catalog entry in `services/config/catalog.rs`; without one the field shows the key as its label and logs a warning. Label and help text are never written in the component.

### Agent panel

The panel is open by default; the backend decides at window creation (below). `window.__settingsAgentPanel` (`"hidden" | "widened" | "overlay"`) and the hook `window.__onSettingsAgentPanel(value)` both end in `applyInitialPanel(value)` of the store, which `App.svelte` registers on mount and removes on destroy. `initialPanelOpen(value)` (`$lib/utils/agentPanelOpen.ts`, tested in `tests/agentPanelOpen.test.mjs`) is true for `widened` and `overlay`: the store then loads the saved width, sets `panelOpen` and requests composer focus, and calls no `settings_agent_panel` because the backend already sized the window. A second call with the same value changes nothing, so the eval's second call cannot reopen a panel the user hid. The sidebar has no agent row.

The panel header is `[Hide] Settings agent · <model> … [New conversation]`: Hide is an icon-only `PanelRightClose` 16 px button with title "Hide panel", first, 6 px from the divider, outside the hit area; the title has no `Sparkles`; the model the agent uses follows a muted `·` (muted, one line with ellipsis; effective id from `$lib/utils/agentModel.ts`: the settings agent model, else the chat model; "No model" in `--warning` whenever `agentModelState` is not `ok`; nothing until settings load); New conversation (`SquarePen`, disabled while the agent runs) is on the right. Both buttons are `ActionIconButton size="lg"` (28 × 28 px, hover `--surface-overlay`); the header is 40 px. While the panel is hidden `App.svelte` shows a floating Agent pill (raw `<button>` with an accent `Sparkles` and the label "Agent", title "Show agent panel", 28 px high, fully rounded, `--surface-raised` background, border and shadow, absolute at the top-right of `.dialog-body`, above the content, below the overlaid panel; an exception in `shared/ui/DOCS.md` → Buttons rule 10); it opens the panel. Opening and hiding the panel slide it in from and out to the right edge by its width with a fade (`fly`, 200 ms, no movement under reduced motion); the panel restored open at window start appears without animation, because only `setPanelOpen` (the user's `openPanel`/`hidePanel`) sets the store's `panelAnimated`. The pill covers the content's top-right corner, so `ModelEditor` and `ModelAssignments` have 48 px top padding (pill 28 + offset 10 + gap 10); a new control placed there must stay below it; once scrolled, their sticky headers sit at the top of the pane, in the button's band, and at a narrow editor pane with the panel hidden the right end of the header can be under the button.

`agent_panel_open` (`ui_state` key `settings-dialog.agent_panel_open`, local to the machine; read only by the backend at window creation) is written by `hidePanel("hide")` (`false`) and `openPanel("reopen")` (the floating button) or `openPanel("search-row")` (`true`); the table is `panelOpenWrite` in `$lib/utils/agentPanelOpen.ts`. `hidePanel("show-link")` writes nothing: a `setting:` link in `AgentMessages` hides the overlaid panel (`docked` false) before `navigateTo`, so the target is visible, and the stored choice stays open. A failed write lands in the store's `error`. `openPanel` and the initial open call `requestComposerFocus()`; `AgentComposer` focuses its textarea when the store's `focusRequest` changes, also on mount while a request is pending.

The composer bar shows `ModelSelector` (model chip, effort chip when the model has effort levels) before the mic with the agent's effective model and effort (`agentModelId`, `agentReasoningEffort` in `$lib/utils/agentModel.ts`). A pick writes an explicit value to `surfaces.settings_agent.generation` via `updateSurfaceModel` / `updateSurfaceReasoningEffort`, so the agent stops following the chat model or effort. The picker is hidden while the effective id is not a text model; reset to "Same as Chat" stays in Settings → Chat. The bar wraps in a narrow panel.

The composer text is the store's `draft` (`setDraft(text)`, `fillDraft(text)` = set and request composer focus); `AgentComposer` binds its textarea to it, a submit sends and clears it, and a dictation transcript is inserted into it at the caret saved at mic press. Placeholder: "Ask about or change a setting…".

Scrolling in `AgentMessages` follows the main chat rule (conversation-dialog `DOCS.md` "Scroll", same `reduceScroll` and `createScrollFollower`). The store's `send` bumps `pinRequest`; the new user message is scrolled to the top of `.messages` and the last user + assistant pair (with the proposal card and error) is a `.pair` with `min-height` of the view minus padding, so the reply streams below it. Content growth (a `ResizeObserver` on `.column`) scrolls only in `follow` mode; following resumes after a user scroll that ends at the bottom, and the empty view after `reset()` (no messages) scrolls to the bottom with no spacer.

`AgentMessages` renders `AgentEmptyState` while there are no messages: a faint-bordered island "Ask instead of searching" with four icon lines, each a label (weight 500, `--text-secondary`) over one muted sentence, icon aligned to the label: "Find an option" (`Search`), "Ask how it is set" (`MessageCircleQuestion`), "Change it" (`PencilLine`), "Secrets stay with you" (`KeyRound`); then three chips ("Where is the context menu shortcut?", "Which model does Quick actions use?", "Where do I set the speech language?"). A chip calls `fillDraft(<its text>)` and never sends. Chips only ask where something is: none sets a value or names a variable. Under the read-only `SecretField` a caption (`EyeOff`, muted) says "Only you see this value. The agent did not receive it."

No-model states: `agentModelState(surfaces, models)` (`$lib/utils/agentModel.ts`, tested in `tests/agentModel.test.mjs`) is `no_text_model` (no model of `type` `text`), `ok` (the effective id of `agentModelId` is a text model), `stale_agent_model` (otherwise, `surfaces.settings_agent.generation.model_id` is non-empty and not among the models) or `no_usable_model`. While it is not `ok` the composer textarea stays typeable, Send is disabled (and `submit` returns), the placeholder is "Pick a model to start" and the model chip stays hidden. In the empty conversation `AgentEmptyState` replaces the island's title and chips with a block and keeps the four lines below it: `no_text_model` shows "The agent needs a model" and "Add model" (`navigateTo("models:new")`); `no_usable_model` and `stale_agent_model` show "Pick a model for the agent", "The agent has no model." / "The agent's model no longer exists.", a select of the text models and "Use" (disabled until a model is picked), and the caption "Also becomes the Chat model, which the agent follows. Or add another model." (the link calls `navigateTo("models:new")`). "Use" runs the plan of `useModelWrites(surfaces, models, pickedId)` in order through `updateSurfaceModel`: `{settings_agent, null}` first when the settings agent id is non-empty and not a text model of `models` (the agent then follows Chat), then `{chat, pickedId}`; a failed write shows its error in the block and is logged. With messages the block is gone and the composer rules above still apply.

Layout depends only on the width of `.dialog-body` (measured with `bind:clientWidth` in `App.svelte`) and the saved panel width, not on the panel mode. `agentPanelLayout(containerWidth, savedWidth)` in `$lib/utils/agentPanelLayout.ts` (tested in `tests/agentPanelLayout.test.mjs`) returns `{ docked, width }`:

- `containerWidth >= CONTENT_MIN_WIDTH + 300` (`PANEL_MIN_WIDTH`): docked. sidebar | content (`flex: 1`) | panel in one row, panel `position: relative` at `min(max(saved, 300), containerWidth − CONTENT_MIN_WIDTH)`, no shadow.
- Narrower: the panel overlays the content's right edge (`position: absolute`, shadow) at `min(max(saved, 300), containerWidth)`.

`CONTENT_MIN_WIDTH` (860 px, sidebar included) is the one constant for the narrowest width at which no settings layout clips or scrolls horizontally. `App.svelte` sets it on `.dialog-body` as `--content-min-width`; the docked panel's `max-width: calc(100% - var(--content-min-width))` keeps the content at that minimum between a container resize and the next measurement. Derived from the CSS widths (box-sizing is `border-box`), to be confirmed in a live run:

- Models: sidebar 220 + model list 280 + editor pane 342 = 842. The pane is padding 24 + 24, card border 1 + 1, card padding 16 + 16 and a card body of 260 px for the widest row that does not wrap (a parameter row: checkbox, label, "inherits <value>" caption, number input). 860 leaves 18 px.
- MCP servers: sidebar 220 + section padding 16 + 16 + server list 220 + gap 16 + editor 320 = 808. An env row is name input 38 % + gap 6 + value cell + gap 6 + remove button 22; the value cell holds the `NAME · missing` chip (about 110) with the × (14), `InsertVariableButton` (26) and gaps (12), at least 160, so `0.62 × editor − 34 >= 160` gives 320.
- Card rows (`ProposalRow`): a column of wrapping flex rows with `min-width: 0` fields, so they fit the 300 px minimum panel width; the diff and output blocks scroll inside their own `<pre>` (`overflow: auto`), deliberately.

The window minimum is 800 px, so the panel always overlays there.

Drag handle: a 9 px hit area centred on the panel's left border (`left: -5px`: 4 px over the content scrollbar's empty right gap, the border, 4 px inside the panel), `col-resize`, pointer capture. At rest only the 1 px `--border-default` border shows; on hover after 150 ms and for the whole drag (until pointer up, cancel or lost pointer capture) a 2 px `--accent` line (`::before`) covers the border. `pointerdown` calls `preventDefault()` (no text selection, no native drag of selected content) and blurs the focused element. While dragging (not on hover), `.dialog-shell:has(.resize-handle.dragging)` in `App.svelte` of the settings window makes the `[data-settings-content]` scrollbar thumbs transparent and sets `col-resize` on the whole window; the panel's own and the sidebar's scrollbars stay. Content scrollers (`[data-settings-content]`) are 10 px wide; vertical thumbs have a 4 px transparent right border with `background-clip: padding-box`, so the visible thumb is 6 px with 4 px empty before the divider; horizontal thumbs and other scrollbars are unchanged. While dragging, the store's `panelWidth` follows `panelRight − pointerX`, clamped by `clampPanelWidth` (`[300, containerWidth − CONTENT_MIN_WIDTH]` docked, `[300, containerWidth]` overlaid); on pointer up the store saves the integer px with `setUiState("settings-dialog.agent_panel_width", px)` (`ui_state.json`, local to the machine). Opening the panel reads it with `getUiState` (`DEFAULT_PANEL_WIDTH` 380 when absent or not a number). A failed read or write lands in the store's `error`. There is no keyboard resize. `global.css` makes every `<button>` text unselectable (`user-select: none`); non-`<button>` clickables are not covered.

Creation: `open_settings_window` decides the panel before the window exists (keys `settings-dialog.agent_panel_open` and `settings-dialog.agent_panel_width`, the monitor work area; see `src-tauri/src/services/settings_agent/DOCS.md` "Panel at window creation"). It creates the window already widened by the saved panel width (`DialogConfig.added_width`) and evals `window.__settingsAgentPanel = "hidden" | "widened" | "overlay"` (and calls `window.__onSettingsAgentPanel?.(mode)`) into the page.

`settings_agent_panel(open)` still returns a mode (`widened` or `overlay`) for later opens and closes; it drives only the window widening and the UI does not read it:

- `widened`: the window grew by the saved panel width (the same key, read by `services/settings_agent/panel.rs` from the managed `UiStateService`; absent or not a number: 380; at least 300).
- `overlay`: the window did not grow. Chosen when the window is maximized, the monitor work area has no room for width + the panel width, or the size did not change within ~300 ms of the resize (tiled window; GNOME Wayland ignores the resize).

Geometry rule: the backend keeps the added width (0 in overlay mode); `save_geometry` subtracts it for `settings-dialog` (`geometry_without_panel`), so the saved width never includes the panel. Closing the panel shrinks the window by the added width; closing the window resets it.

State is `getSettingsAgent()` (`$lib/stores/settingsAgent.svelte.ts`): messages (user text; the assistant reply state and the reduction of stream events live in `$lib/utils/agentReply.ts`: text from `chunk` events, tool calls as stored `ToolCall`s: `tool_call_start` appends the call's `{{tool_call:<id>}}` marker to the text (as main chat, so a call shows when it starts, not with the next round's text) and pushes the call, `tool_call_done` sets `result`, `error`, `status` and `completed_at`; thinking of each iteration is kept, a `tool_call_start` closes the iteration, and `AgentMessages` shows it in `ThinkingBlock` above the reply (main chat keeps only the last iteration's thinking); when `send` ends it clears the thinking-active flag and calls still `in_progress` or `pending` become `cancelled`; `AgentMessages` splits the text at the `{{tool_call:<id>}}` markers with `$lib/utils/toolCallMarkers.ts` (shared with `AssistantBubble`) and renders each run of markers as a `ToolCallGroup` at its position, skipping ids without a stored call; below the last reply `ProcessingIndicator` ("Generating") shows while `showsProcessing(reply, running)` holds: the agent runs, the reply is not thinking, and either it has no text, no thinking and no call `in_progress`/`pending`, or every call is `completed`, `failed` or `cancelled` — the rule of `AssistantBubble`), `running`, `error`, `send`/`cancel`/`reset` over `$lib/services/settingsAgent.ts`. It calls `settings_agent_reset` once on load; the conversation lives in the module state, so it survives closing the panel and ends with the window. `AgentComposer` has a `beforeSend` snippet slot (`AgentPanel` fills it with the model selector and, when `agentModelHasBuiltinSearch` holds, a Web search toggle: an `ActionIconButton` with lucide `Globe`, label "Web search", `active` and `aria-pressed` while `web_search` is in `surfaces.settings_agent.generation.enabled_tools`; a click calls `setSurfaceTool("settings_agent", "web_search", !on)`, the same entry as the "Web search (built-in)" checkbox of the agent tools, and a failure is logged with `logError`) and a mic button (`Mic`) that records into the composer itself, without the pill (backend: `src-tauri/src/services/speech/DOCS.md` "Composer dictation"). `useComposerDictation({ owner: "settings", insert })` (`shared/widgets/`, shared with the main chat) keeps the state `idle | recording | transcribing | error`; a mic press saves the textarea selection and `start_composer_dictation` begins. From then on until the transcript is inserted, the session is cancelled or the error dismissed, the textarea is `readonly` and Enter sends nothing; `ComposerDictationBar` replaces the button bar (level meter and `m:ss` with Cancel and Finish; "Transcribing…" with Cancel; the error message with Retry and Dismiss, a start refusal with Dismiss only). The transcript replaces the saved selection of `draft` (`insertText`), and the textarea is focused with the caret after it; an empty transcript inserts nothing; it is never sent, copied or logged. The mic is disabled while the agent runs and while `dictation-busy-changed` / `get_dictation_busy` name another owner, with the tooltip "The pill is recording" or "Dictation is running in Chat". Unmounting the composer (Hide, the show-link auto-hide) while recording or transcribing calls `cancel_composer_dictation`; closing the window is cancelled by the backend.

Links: the assistant writes `[label](setting:<key>)`, or `[label](setting:section:<id>)` for a whole section (`<id>` one of the 12 section ids; `parseSectionLink` in `$lib/utils/settingLinks.ts`). `$lib/utils/settingLinks.ts` (`parseSettingLink`, `showSettingLinks`) relabels them "Show" before markdown rendering; a click on `setting:` calls `navigateTo(key)`, any other link opens through `openUrl`.

### Missing environment variables

`MissingEnvList.svelte` sits above sidebar and content in `src/windows/settings-dialog/App.svelte` and renders only when `getMissingEnvRefs()` (backend `get_missing_env_refs`) returns names: each `${VAR}` without a value on this machine with the labels of where it is used, plus an "Add value" link that opens `SecretField` inline under the name (no agent involved); closing it refreshes the list. It refreshes on `settings-changed` (`onSettingsChanged`) and window focus. The same set drives the startup/sync toast (`src-tauri/src/services/DOCS.md`).

### Environment section

`SectionEnvironment` (sidebar "Environment", group App) lists `getEnvVars()` (`get_env_vars` in `$lib/services/settings.ts`) in two cards, "Secrets" first, then "Variables", split by the `secret` flag with `groupByKind` (`$lib/utils/envVarOptions.ts`, each group sorted by name). A card shows its rows, a muted "No secrets." / "No variables." line when the list is loaded and the group is empty, then its own add form. The hint reads "Pick these in models and MCP servers. Names and descriptions sync; values stay on this machine." It refreshes on mount, `settings-changed` and window focus. Every change goes through `applyEnvVarOperation(operation)` (`apply_env_var_operation`, operations `add_env_var`, `update_env_var`, `rename_env_var`, `delete_env_var`; each writes a change-log entry, so Undo is in `ChangeHistory`) and then reloads the list; a rejection shows its message at the row (at the add form of its card for an add; the `row N: ` prefix is cut; delete of a used name lists the usages) and changes nothing locally. Names are checked client-side with `^[A-Za-z_][A-Za-z0-9_]*$` before sending.

Add form per card: name, description, "Add secret" / "Add variable" (`Plus` + label; Enter in an input adds); `secret` is `true` in the Secrets card and `false` in the Variables card. After an add the value field opens under the new row.

Row header: name, state "set" / "missing" (`--success` check / `--danger` alert), "Set value" / "Change value" (`KeyRound` + label; opens `SecretField` with `exists` = set and `masked` = the secret flag, so masked in Secrets and plain in Variables), then the icon-only `Pencil` ("Edit secret" / "Edit variable") and `Trash2` ("Delete secret" / "Delete variable") per-row actions; Delete is an inline two-step confirm: "Cancel" and "Delete secret" / "Delete variable". Row body: the description when non-empty, then `Used in: <labels>` or "not used". Values are never held by the section.

"Edit" opens a panel in the row, one row at a time: name and description inputs prefilled with the stored values, "Save", "Cancel" and "Move to Variables" (Secrets row) / "Move to Secrets" (Variables row; `ArrowRightLeft` + label). Enter saves, Escape cancels (`stopPropagation()`). The edit state is keyed by the stored name, because rows are keyed by it. Save runs in this order: a changed name that fails the pattern shows the name error at the row and sends nothing; a changed description sends `update_env_var` (old name, new description, stored `secret`); a changed name then sends `rename_env_var`. When both change, the change log gets two entries. A rejection shows at the row and stops: after a failed description update the panel stays open; after a failed rename the row, its open panel with the typed name and the already saved description stay. Success closes the panel and clears an open value field of the old name. Nothing changed: the panel closes without an operation. "Move" sends `update_env_var` with the stored name and description and the flipped `secret` at once; the row then renders in the other card.

### Proposal card

`agent/ProposalCard.svelte` renders the store's `proposal` (event `settings-agent-proposal`, one card; a new proposal replaces it, a refresh keeps the checkbox state and typed values because the card is keyed by `proposal_id`) after the messages in `AgentMessages`. `ProposalRow` per row: checkbox (checked by default), label, each effect as before → after (setting effects) or a line diff (`lineDiff` in `$lib/utils/lineDiff.ts`, file effects: skill and prompt files), the test result (`OK · <ms> ms` or the exact error; skill output and sample input in collapsed "Output" and "Sample input"; `sample_input` comes from the proposal payload, `null` for other rows), "Test" (only for model, skill and MCP rows; `settings_agent_test_row`) and "Show" (`navigateTo` with the setting's concrete key; skill files navigate with `skills[<slug>]`, which `navigateTo` resolves without a catalog entry by switching to Skills and setting `selectedItem`, which `SectionSkills` keeps as the requested slug until the skills store contains it, then selects; prompt files switch to Prompt Base; a secret effect has no "Show"). A stale row shows "changed since proposed"; a `stale_rows` result of Apply marks those rows stale in the held proposal; "Refresh" (`settings_agent_refresh`) is offered and Apply stays disabled until none is stale. Apply sends one boolean per operation index and the typed values (below); `stale_rows` or `error` (dependency errors name the dependent rows; a selected `set_env_value` row without a value names its variable) show on the card and nothing is written. Success shows "Applied" and "Undo"; the entry id is in `proposalOutcome` of the store. "Undo" (`undoProposal` of the store) undoes the whole card with `undoChange(entryId, false)`, the outcomes as in `ChangeHistory`: `conflicts` shows `UndoConflicts` with "Undo anyway" (`force: true`), `skipped` shows "Secret backup is on <host>", an error shows on the card, `undone` shows "Undone", a final state: no Apply, no Undo, checkboxes and value inputs disabled. To apply again the user asks the agent for a new card (the backend drops the proposal at Apply). Reject closes the card.

Value input: a row with `env_value` (`set_env_value`) shows an input under the label, a password input with the reveal toggle (`ActionIconButton` `Eye`/`EyeOff`, labels "Show value" / "Hide value") when `env_value.secret`, a plain text input otherwise; when `env_value.set` the current value is loaded once on mount with `get_secret_value` (a failed load shows the error and leaves the input empty). There is no Save button: the card's Apply writes. The typed values live only in `ProposalCard`'s `$state` record (variable name to value); the store, events, logs and `ui_state` never hold one, and `{#key proposal_id}` drops them with the card. They leave the card only as the `values` argument of `agent.applyProposal(selected, values)` (the selected `set_env_value` rows with a non-empty value) and `agent.testRow(row, values)` (all non-empty values), which pass them on to `settings_agent_apply` and `settings_agent_test_row` and keep nothing. The effect line of such a row shows the variable name only.

Waits and new destination: a row with `waits_for` shows "waits for a value of <names>" in place of its test result, and no "Test" button, while any of those names has no value in the card. A change of a value re-tests, after 500 ms without input or at once on blur, each row whose `waits_for` has that name, whose waited names all have a value and whose `new_destination` is `null`; a value loaded by the prefill re-tests nothing. A row with `new_destination` shows that text in `--warning` until the card is applied; it is tested only by a click on its "Test" button, and a successful test leaves the warning in place.

### Secret field

`SecretField.svelte` (props `name`, `purpose`, `exists`, `masked` (default `true`), `readonly` (default `false`), optional `onclose(outcome)`; the type `SecretOutcome` is exported from its module script): an existing value (`exists`) is loaded on mount with `get_secret_value` for masked and unmasked fields; masked shows it as a password field with a reveal toggle (`ActionIconButton` `Eye`/`EyeOff`, labels "Show value" / "Hide value", visibility only), `masked: false` as a plain text input without the toggle (for variables that are not secrets, e.g. a path). Save (`save_secret`, writes at once as its own change, independent of any card) and Cancel; Save stays disabled while the value is empty or equal to the loaded one, so opening and saving without an edit writes nothing. A failed load shows the error and leaves the field empty with the "Enter a new value" placeholder. `onclose` gets `saved` or `cancelled`; the value lives only in the component state, never in a store, log or event. The Environment section's Secrets card, `MissingEnvList` and `EnvVarPicker` use this editable mode; the agent does not.

Read-only mode (`readonly`, used for `settings_secret`): `AgentMessages` renders one for each name in `secretViews` of an assistant message, below that message's content. The component loads the value with `get_secret_value` on mount and shows it as bullets with the reveal toggle (`Eye`/`EyeOff`); no input, no Save, no Cancel, `onclose` is not called. A load that returns none or an empty value shows "not set", a failed load shows its error. The store appends the name of the event `settings-agent-secret-view { name }` to `secretViews` of the last assistant message (`emptyReply` starts it empty), so the view keeps its place in the conversation; `reset` clears it with the messages. The agent does not see the value and the field cannot change it: a change goes through a `set_env_value` row of a card.

### Persistence — auto-save with debounce

No Save/Cancel buttons. Every input persists on change:

- **Text inputs** (display name, model id, base URL, API key, group, custom param values) — debounced via `scheduleSave(false)`. Debounce is `store.settings.autosave_debounce_ms` (each editor gets it as a `debounceMs` option or prop, falling back to `?? 1000`); every autosave site reads it from here. 1000ms is tuned to fire only when the user has actually paused (typical inter-word gap is 250–400ms; 200ms fires mid-sentence).
- **Discrete controls** (segmented buttons, selects, checkboxes, slider toggles) — `scheduleSave(true)` = persist immediately, no debounce.
- **Range sliders and number inputs** — fire on every `oninput` and must debounce. `ParametersKnown` passes `immediate: false` as the third argument of its `onChange` callback for these; the checkbox and the reasoning-effort select pass nothing and stay immediate. Saving a slider drag immediately would write the skill/model file once per animation frame, each write emitting a change event and a full store refresh. The known-parameter override checkbox is the gate: unchecking it sends `null` to drop the override entirely.

Save state is owned by `useSaveTracker()` (`$lib/stores/saveTracker.svelte.ts`) — a small rune-based state machine that owns the debounce timer, the reentrancy guard, the `now`-tick interval driving the saved-stamp expiry, and a single try/catch that captures errors. It exposes `state` (`idle | dirty | saving | saved | error`), `tooltip`, and `error`, plus `scheduleSave(persistFn)`, `flush()`, `runAction(fn)`, `cancel()`, `attachKeyboard()`, `attachBeforeUnload()`, and `destroy()`. The tracker owns debounce, flush, Cmd/Ctrl+S and unmount-flush only; it does not draw anything.

The window shows **one** save status, from `getSaveStatus()` (`$lib/stores/saveStatus.svelte.ts`; state and tooltip are derived in `$lib/utils/saveStatus.ts`). It is fed by two sources: `trackedInvoke` (`$lib/services/trackedInvoke.ts`) wraps every Settings write (`invokeWrite` and the skill, prompt, keyterms, secret and env services) and reports its start, success and failure; each `useSaveTracker` registers itself with the store on creation, reports its `dirty` flag and unregisters in `destroy()`, so an edit waiting for its debounce shows as dirty. A new write service goes through `trackedInvoke`, a new editor through `useSaveTracker` with `destroy()` on unmount; neither renders a status of its own. `<SaveStatusIndicator />` (in `$lib/components/shared/widgets/`, no props) renders the store state: 6 px dot + transient "✓ saved" / "⚠ save failed" stamp + tooltip. Clicking the "save failed" stamp copies the error and swaps the stamp to an uncoloured "✓ copied" for `COPY_FEEDBACK_MS`.

The pattern in `ModelEditor.svelte`:

```ts
const tracker = useSaveTracker({ debounceMs });

onMount(() => {
  tracker.attachKeyboard(window);
  tracker.attachBeforeUnload(window);
});
onDestroy(() => tracker.destroy());

function scheduleSave(immediate: boolean) {
  if (immediate) void tracker.flush(persist);
  else tracker.scheduleSave(persist);
}
```

`tracker.destroy()` must run on unmount to clear timers and detach window listeners; it also fires the pending debounced save before tearing down, because unmount is a normal way to leave an editor (switching sidebar section, or picking another skill through the `{#key}` block) and a 1000 ms debounce is easy to beat.

Saves are **queued, never dropped**. A save arriving while another is in flight waits for it and then runs — the earlier `if (saving) return` guard silently discarded the newer edit while still reporting success, so the last change before a rapid second edit was lost. `dirty` only clears when nothing is queued behind the save that just finished.

Discrete actions that aren't auto-saves (delete, duplicate) should go through `tracker.runAction(fn)`, not `flush(fn)` (`SkillEditor` does; `ModelEditor` still passes its delete and duplicate to `flush`): it persists pending edits first, then runs the action, and its `true`/`false` reflects the action itself. `flush(fn)` only queues `fn` as the next autosave — a concurrent edit can replace it, so an action passed to `flush` may never run while still returning `true`. Callers branch on the boolean to decide whether to advance UI (e.g., switching selection after a successful delete).

The indicator is mounted in exactly three places, each right after the title of what is shown and outside it: `SettingsSection` renders it after its `h2` whenever `title` is set (the search highlight styles the `h2` only, not the indicator), `ModelEditor` after its `h1`, `ModelAssignments` after its `h1` (both in an `.editor-header` row). The `ModelEditor` and `ModelAssignments` headers are sticky (`position: sticky; top: 0` inside `SectionModels`' `.editor-pane`, opaque `--surface-base`, `--border-faint` bottom border, `z-index: 1`): `ModelEditor`'s `.sticky-head` wrapper holds the `h1` row with the indicator and the "Used by" line, `ModelAssignments`' `header.editor-header` the `h1` row; the 48 px top padding scrolls away and the header keeps 16 px top padding; form controls get `scroll-margin-top` from the measured header height (`--sticky-head-height`), so a field focused by Tab is not left under it. No editor (`SkillEditor`, `SectionMcpServers`, `PromptEditor`, `SttKeytermsEditor`, `SectionPromptBase`, `WebviewProvidersEditor`, `SectionContextMenu`) renders its own dot; they only keep their `useSaveTracker`. The tabbed prompt section therefore shows one status for all its tabs. The title sits at the left of the content and the floating Agent pill at its top right, so the pill does not cover the indicator.

A load failure is not a save failure: `PromptEditor` and `SttKeytermsEditor` render the error message inline where the content would be (`.load-error`), never through the store. `SkillList` logs a failed reorder with `logError`; the status shows it through `reorderSkills` → `trackedInvoke`.

### Draft state, not direct mutation

`ModelEditor` clones the incoming `model` prop into a local `$state` `draft` and edits the draft. A `$effect(() => { const m = model; untrack(() => { draft = structuredClone(m); ... }) })` resets the draft when the parent swaps to a different model. The parent uses `{#key selectedModel.id}` so switching models fully remounts the editor, which combined with `untrack` prevents stale-draft leaks across selections.

`structuredClone` (not spread) — required because `parameters` is nested.

`SkillEditor` mirrors the same shape for the `skill` prop. The `{#key}` remount is a convenience (it resets local UI state like `confirmDelete`), never the mechanism that loads fresh data — the sync effect must do that on its own, see "Reactivity gotchas".

### Validation

Client-side: `ModelEditor.validate()` populates `validationErrors: Record<string, string>`; `persist()` early-returns on invalid state, with a red border and field error.

Backend: `ConfigService` rejects an invalid write with `<message> (setting: <concrete key>)`. Every write in `services/settings.ts` goes through `invokeWrite`, which parses the error (`parseSettingError`) and calls `store.reportWriteError`: a key lands in `store.fieldErrors` (read with `store.fieldError(key)`), an error without a key becomes `store.toastError`, shown by `SettingsErrorToast` (auto-dismiss after 6 s). A successful write clears `fieldErrors`. `ModelEditor.errorFor(field)` shows `validationErrors[field]` or the backend error at `models[<id>].<field>`; a new field editor that wants backend errors reads `store.fieldError(<concrete key>)` the same way.

Custom param errors live in `customErrors` keyed by `entry.id` (the parse function in `ParametersCustom.svelte`'s module script returns `{ extra, errors }`).

### Sections as cards

Inside a section, group related fields in `<section class="card">` with an uppercase `<h3>` heading (e.g., "Basic", "Connection", "Capabilities", "Parameters", "Danger zone"). Card styles live in `ModelEditor.svelte`'s scoped style — copy them when adding a new section to keep visual rhythm consistent.

### Danger zone

`DangerZone.svelte` is the last card of `ModelEditor` and `SkillEditor`: red border (`var(--danger-border)`), separated visually. Props: `noun`, `name` (shown in the confirm), `compact`, `warning` snippet, `onDuplicate`, `onDelete`, optional `onExport`. Destructive actions use a two-step inline confirm — never an OS dialog or a modal-on-modal.

```
[Delete model]  →  "Delete X? [Cancel] [Delete X]"
```

If the action affects other state (e.g., a model referenced by a surface), surface that warning inline in the confirm prompt — don't block, just inform.

### Labels & controls

- Left-align labels, full-width controls below (single-column form). For very short selects/segmented controls (Type), `width: fit-content`.
- Label = what it does ("Store request/response on provider"). `<p class="helper">` underneath = one-line tradeoff/effect.
- Toggle labels describe the **state**, not the action. Checkbox sits left of the text, both clickable via the wrapping `<label>`.
- `lucide-svelte` icons only — never raw SVG. Sizes from `$lib/constants/ui.ts` (`ICON_SIZE.sm`, `.md`).

### "Override or use default" pattern

`ParametersKnown.svelte` shows each param with a leading checkbox. Unchecked = inherit (sends `null`); checked = enable the slider/input pre-filled with a value. This keeps the form short and makes "I haven't touched this" visually distinct from "I set it to 0".

Pass the `inherited` prop (the surface parameters the editor falls back to — for skills, `surfaces.quick_actions.generation.parameters`) whenever there is a real inheritance chain. It drives two things: an `inherits <value>` caption next to every unchecked param, and the prefill used when the box is checked. Checking a box must not silently change the effective value — prefilling `reasoning_effort` with the first allowed level (`minimal` for OpenAI effort models) while the surface inherits `medium` is a silent downgrade the user never asked for. Static defaults (`temperature: 0.7`, `max_tokens: 4096`) are the fallback when nothing is inherited.

Reasoning effort is a `<select>`, not an `<input list>` + `<datalist>`. Browsers filter datalist suggestions against the field's current text, so a field already holding `medium` offers exactly one suggestion and looks broken; free text also meant every keystroke fired an immediate save of a half-typed level. The row also renders when the value is set but the model reports no effort support (deleted model, capabilities changed) — with a warning — so a stored value can never become invisible and unremovable.

### Skill "Offered in"

`SkillEditor` shows `offered_in` as two checkboxes, "Context menu" and "Recording widget" (`pill`). Both checked sends `offered_in: null` (no `offered_in` line in the file, offered everywhere); both unchecked sends `[]` (`offered_in: []`, offered only in the chat); one checked sends that value. `persist` always sends the field, because `update_skill` writes exactly the frontmatter it receives — omitting it would erase a restriction on every edit of another field. The chat `/skill` autocomplete ignores the field.

### Missing or unlisted model references

A skill pins a model by id and nothing rewrites that id when the model is deleted, so the editor must handle "the pinned id resolves to nothing". `SkillEditor` renders a synthetic `<option>` for such an id (`<id> — no longer exists` / `— is not a text model`) plus a `warn-text` helper line. Without it the `<select>` has no matching option, silently renders blank, and the skill looks like it inherits while `resolve_quick_action_model` fails at run time (a pinned id never falls back to the Quick Actions model — that's deliberate, an unrunnable skill should say so rather than quietly run on a different model).

The same id also yields no capabilities, so anything capability-gated must degrade to "show the stored value with a warning" rather than disappearing — see the reasoning-effort row in `ParametersKnown`.

The inherit option and an explicit pin to the same model read almost identically, so the option list marks the model that is currently the Quick Actions one.

### Env var references

The model API key (`ModelEditor`, `CreateModelDialog`) is an `EnvVarPicker`: a `SelectDropdown` over the listed variables (`getEnvVars()`, refreshed on `settings-changed`) plus "New…"; there is no input that accepts a literal key (the agent rejects literals too). The stored value is `${NAME}`; a picked name emits `${NAME}` and the editor saves at once. Three states come from `classifyReference` (`$lib/utils/envVarOptions`, tested in `tests/envVarOptions.test.mjs`):

- listed: shown as `NAME`, or `NAME (missing)` when no value is set on this machine;
- unlisted reference: `NAME (not listed)` with an "Add to list" button (`add_env_var`, secret on, empty description);
- stored literal: `Literal key` with "Move to a variable": the name/description form, then an empty `SecretField` (the literal is not shown or copied; type the key again); the reference replaces the literal only after the value is saved.

"New…" order: `add_env_var` (inline name/description form, secret on), `SecretField` for the value, then the model write; cancelling the value step still sets `${NAME}`, shown as missing. A rejected operation shows its message under the picker.

`parseEnvRef()` lives in `$lib/utils/envVarOptions` (don't reimplement the regex).

### Surface references

Where a model is used shows as "Used by" tags (`ModelUseTags.svelte`) in three places:

1. `ModelList` rows: tags under the model id and chips, none for an unused model. The row is a `div` holding a selecting `<button>` (name, model id, chips) and the tags, since a button may not contain buttons; hover and active styles sit on the whole row.
2. `ModelEditor` header: a "Used by" line followed by the tags; with no uses, "nothing — " and a link "assign in Assignments ›" (`onShowAssignments`).
3. Delete warning (`DangerZone` `warning` snippet, only with uses): "It is used by <list>." with the same texts as the tags, comma-separated, same order. The warning keeps the `.warn` colour — destructive intent justifies the warning palette.

Tag kinds and texts (`modelUseLabel` in `$lib/constants/surfaces`, shared by tags and warning):

- surface, stored on the surface: solid tag `SURFACE_LABELS[surface]`;
- surface inheriting the Chat model (empty model of Quick actions, Title generation, Settings agent): dashed tag `<label> (same as Chat)`;
- skill pin: tag `skill: <name>`.

Click: a surface tag calls `onShowUse(surface)`; `SectionModels` selects Assignments, sets the local `highlightedSurface` for 2000 ms (a new click restarts the timer), scrolls `#assignment-<surface>` into view and `ModelAssignments` draws the `SettingField` highlight style on that row. The highlight is local state of `SectionModels` because `navigateTo` selects only model ids. A skill tag calls `navigateTo("skills[<name>]")`. A tag click calls `stopPropagation()`, so it never selects the row.

Single source: `store.usesByModel` (`Map<modelId, ModelUse[]>`) and `store.getUsesForModel(id)` (`ModelUse[]`), both from `modelUses` in `$lib/utils/modelUses.ts`: stored and inherited-from-Chat surface uses in the order chat, quick_actions, title_generation, settings_agent, speech_to_text, then skill pins. Never recompute the mapping ad hoc; list, editor header and delete warning must read from the store so they stay in lockstep.

The server editor's `toolUses(server, tool, surfaces)` (`$lib/utils/toolUses.ts`) is not such a source: only `SectionMcpServers` reads it, so it is called there and no derived value lives in the store.

`--warning` is reserved for issue states only ("issue / attention required"); a binding to a surface is not one. Filled circles are reserved for transient state (the save indicator in `SaveStatusIndicator`); persistent structural facts get text.

### Reactivity gotchas (Svelte 5)

- Top-level state (`let x = $state(...)`) and effects in this directory follow Svelte 5 runes mode.
- `useSaveTracker` is called from `$effect` in half the editors (`PromptEditor`, `SttKeytermsEditor`, `SectionPromptBase`, the `customEntries` and body effects in `SkillEditor`/`ModelEditor`), so **nothing inside the tracker may be a signal the tracker itself reads and writes**. `pending` and `saveTimer` are deliberately plain `let`s: as `$state` they made `scheduleSave` register `saveTimer` as a dependency of the calling effect (`if (saveTimer) clearTimeout(saveTimer)`) and then invalidate it (`saveTimer = setTimeout(…)`) — an infinite effect loop that aborts the flush with `effect_update_depth_exceeded` and leaves controlled `<textarea>`s reverting every keystroke (caret moves, character never appears). The public mutators wrap their synchronous bodies in `untrack()` for the same reason. Reactive `hasPending` comes from a separate write-only `$state` flag; assigning a signal, unlike reading one, creates no dependency.
- When mirroring a prop into local `$state`, read the prop **outside** `untrack` and put everything else — including the `tracker.dirty / saving / hasPending` guard — inside it (`ModelEditor.svelte` is the reference). The prop must be the only dependency, so the effect re-syncs when fresh data arrives and never at any other time. `SkillEditor` had this inverted: `skill` was read inside `untrack` and the tracker flags outside, so the effect re-ran the moment a save finished — restoring the *pre-save* prop over the value just entered, because the store refresh (event → `list_skills_full`) lands later — and never re-ran when the refreshed prop finally arrived. Symptoms were "the value only shows up the second time I select the skill", checkboxes bouncing back after one click, and edits reverting and then being written back to disk by the next autosave.
- `$effect` that watches an array (e.g., `customEntries`) and fires a debounced save: reference the array first (`customEntries;`) before the timer logic — that's what registers the dependency.

### Prompt editor

`PromptEditor.svelte` is the single component for any prompt slot. It loads via `getPrompt(kind)`, autosaves on change with the `autosave_debounce_ms` debounce, and supports `Cmd/Ctrl+S` to flush immediately. There is no Save button — the only persistence affordance is the window's save status after the section title (see "Persistence" above). The file path is hidden behind a `FilePathReveal` (`…`) next to the title (custom paths require manual JSON edit).

Only `kind: "environment"` shows the placeholders affordance: a `{ }` `ActionIconButton` (`Braces`, label "Insert placeholder", `active` while the popover is open) in the title row opens an `EnvPlaceholdersPopover` anchored to the button. Clicking a chip calls `HighlightedTextarea.insert(token)` and closes the popover. Other prompts get a description that says they are sent verbatim — no placeholder substitution happens for them.

A `PromptEditor` or `SttKeytermsEditor` inside a fixed-height wrapper (Chat 280px, Speech 320px) must fit in it: the Chat and Speech `PromptEditor`s and the keyterms raw pane pass `minHeight={0}` to `HighlightedTextarea` (its default 320px min-height plus the editor header is taller than the wrapper), and the keyterms chip pane has no min-height, so it shrinks and scrolls. Content taller than the wrapper is painted over the next field.

### Section shells & tabbed prompts

`SettingsSection.svelte` is a shared scaffold every section can use: optional title + hint header (with a thin `--border-faint` divider) and a scrollable padded body. Use it for sections that have a "page" feel (`SectionPromptBase`, `SectionChat`, `SectionSpeech`); the models section keeps its own list+editor split layout but should still match `SettingsSection`'s padding rhythm where possible.

List + editor sections (`SectionModels` with `ModelList`, `SectionSkills` with `SkillList`): the list has no background of its own, list and editor share the section background and are divided only by the list's `border-right: 1px solid var(--border-faint)`, so both read as one block. A darker list background stood as a separate strip next to the lighter editor. The selected row is `--accent-bg-soft`, hover `--surface-overlay-faint`; both are translucent, so they keep their contrast on the section background. `SectionMcpServers` uses bordered cards on the section background instead of a list pane.

Content column: every section sits in one column of the same width, `--column-width` (1040 px), left-aligned in `.content` right after the sidebar, so the column's left edge does not move between sections. Inside the column each section keeps its own form widths, left-aligned; never center a section by its own width. `SettingsContent` defines `--column-gutter` (`max(0px, 100% - var(--column-width))`, right-only; a percentage, so it resolves against the containing block where it is used and is correct only on an element whose containing block spans the whole `.content` width). Applied as `.head` `margin-right` (the header divider spans the column, not the window) and added to the `.body` right padding in `SettingsSection`, and in `SectionModels` as the editor pane's `padding-right`; the model list has no margin and touches the sidebar, while the Skills list keeps the 24 px `.body` left padding. The scroll containers (`.body`, the models editor pane) keep the full `.content` width, so their scrollbar stays at the right edge of the content area; only the Skills editor pane, a scroller inside `.body`, has it at the column's right edge. The free width beyond sidebar 220 + column 1040 is split in half: the left half widens the sidebar by the lead `L` so its background reaches the window's left edge, the right half stays free for the docked panel or the gutter. `sidebarLead(containerWidth, dockedPanelWidth)` in `$lib/utils/agentPanelLayout.ts` (tested in `tests/agentPanelLayout.test.mjs`) returns `L = max(0, min((W − 1260) / 2, W − 1260 − R))` with `W` the `.dialog-body` width, `1260 = SIDEBAR_WIDTH + COLUMN_WIDTH` and `R` the clamped `panelLayout.width` while the panel is open and docked, else 0 (never the raw saved width). `App.svelte` passes `L` to `SettingsSidebar` as `lead`: the sidebar is `220 + L` px wide through the `width` prop of `Sidebar`, and `.sidebar-inner` has `padding-left: L`, so the items keep their 220 px at the sidebar's right end. With the agent panel docked beside the content, `.content` is the width left by the sidebar and the panel: `L` shrinks first (to 0 once `W − 1260 <= R`), then the right gutter, which is 0 while `.content` is at most `--column-width`; the column then stays against the sidebar. With the panel overlaid the column stays left-aligned under it and `L` is computed with `R` 0.

`SectionPromptBase` uses a tab strip in the section header — only one `PromptEditor` is mounted at a time and fills the available height. This replaces the old "stacked card-soup" layout where every prompt rendered a full-bordered card stacked vertically. Tabs are uppercase-tracked labels, active tab uses a 2px bottom border in `--accent` (mirrors the sidebar's left-border marker, single-accent rule).

`SectionPromptBase` additionally renders a "Preferred name" identity card above the tabs — a single-field `TextInput` capped at 60 chars (live counter on the right edge, turns `--danger` if `maxlength` is somehow exceeded). It autosaves through `useSaveTracker` + `updateSetting("preferred_name", …)`. The counter belongs to this card; the save status is the one after the section title.

Editor body width is capped (760px for prose-style prompts, 960px for environment with its placeholders popover; hardcoded in the section styles) to keep long prompts readable; don't let the textarea fill arbitrary window sizes.

Save flow goes through `$lib/services/prompts.ts` → backend `save_prompt` Tauri command → `ConfigService::write_prompt` → `PromptStore` (atomic tempfile + rename). Backend emits `prompt-changed` Tauri event after each save.

### Chat and Speech sections

`SectionChat` shows the default chat model, reasoning effort (as the model editor's effort select: "None" first, all levels when the model does not advertise effort, a saved value the model does not accept shown as "not accepted by this model"; plus "Default" = `null`), the chat's MCP tools (`SurfaceToolsPicker`), the title generation model and the settings agent model (the empty option of both is "Same as Chat (<chat model name>)" from `sameAsChatLabel` in `$lib/utils/modelUses.ts`, = fall back to the chat model), its reasoning effort (options gated by the capabilities of the effective model, as for chat; an empty value falls back to the chat's reasoning effort) and its MCP tools (`SurfaceToolsPicker`, "Settings agent tools"), the title generation prompt (`PromptEditor` kind `title_generation`), and `WebviewProvidersEditor`.

`SectionSpeech` shows STT model, language (empty = `null`), `no_verbatim`, the STT prompt (`PromptEditor` kind `speech_to_text`), keyterms (`SttKeytermsEditor`) and the `speech_to_text_toggle` shortcut, then the recording and failure-handling cards.

`ShortcutField` (prop `action`) lists every shortcut of `action` from all keymap groups of the current OS (`macos` when `isMac`, else `linux`) with `actionShortcuts` from `$lib/utils/keymapShortcuts.ts` (sorted by the stored string, shown through `formatShortcut`: `ctrl+f2` → `Ctrl+F2`), each as a chip; "Not set" when there are none. × on a chip removes that one with `removeShortcut` (the stored string); "Add shortcut" (`Plus` + label) enters capture: the next keydown with at least one modifier and one key becomes the string `cmd|super`, `ctrl`, `alt`, `shift` (in that order, `cmd` for Meta on macOS, `super` elsewhere) plus the key (`a`, `1`, `f1`…`f24`, `space`, `tab`, `enter`, `backspace`, `delete`, `up`, `down`, `left`, `right`, `home`, `end`, `page_up`, `page_down`), joined by `+`, and is saved with `addShortcut`; Escape or blur cancels. The other shortcuts of the action stay bound. The capture handler calls `stopPropagation()`. The field sits in `SettingField key="keymaps.<action>"`, so a collision error from the backend shows at the field; write failures are logged with `logError`.

`WebviewProvidersEditor` edits the whole `webview_providers` list (name and URL rows, add, remove) and saves it with `updateSetting` — text debounced, remove immediate. Existing ids are kept; a new row gets its id on first save: the name lowercased with characters outside `[a-z0-9_-]` replaced by `-`, suffixed `-2`, `-3`… when taken. Rows without a name are not saved. The list is seeded from the store on mount and not re-synced from later external changes.

`SurfaceToolsPicker` (props `surface`: `"chat" | "settings_agent"` and `enabled`: the surface's list) renders the checkboxes of qualified `server.tool` names from `listMcpTools()` without the tools with `disabled` (switched off in the server editor; empty state "No MCP tools available.", shown below the built-in checkbox when there is one). It fetches on mount and again on every `settings-changed` (unlistened on destroy), so a tool switched off disappears at once. The "Web search (built-in)" checkbox (value `web_search`) is above them, shown for `surface="settings_agent"` when the effective agent model is OpenAI (or unset provider) in Responses mode (or unset `api_mode`), per `agentModelHasBuiltinSearch` in `$lib/utils/agentModel.ts`, and for `surface="chat"` when the chat model (`surfaces.chat.generation.model_id` in `store.models`) has `provider === "openai"` (the composer's rule); a stored `web_search` stays in the list while the box is hidden. A toggle writes one name with `setSurfaceTool(surface, tool, on)` (`set_surface_tool`), never the whole list; a failed write is logged with `logError`.

`SectionContextMenu` shows the quick actions model (the empty option is "Same as Chat (<chat model name>)") and reasoning effort (options follow the effective model, `quickActionsModelId`; `effortOptions` from `$lib/utils/effortOptions.ts`, shared with `SectionChat`), `menu_section_order`, `recent_apps_count` (`NumberInput`, min 0) and `menu_digit_select_delay_ms` (both go through one `useSaveTracker`: the edit shows dirty, saves after `autosave_debounce_ms`, Cmd/Ctrl+S or unmount flushes it, one persist writes each pending key) and `ShortcutField` for `open_context_menu`, `execute_active_prompt`, `set_context_value`, `append_context_value`, `clear_context`. The order list shows the ids present in the setting, named (`chat` Chat; `skills`, `prompts`, `SkillProvider` Skills; `models` Models; `settings` Settings; `speech`, `SpeechMenuProvider` Speech; `lastInteraction`, `LastInteractionMenuProvider` Last interaction; `context`, `ContextMenuProvider` Context; an unknown id as is). HTML5 drag-and-drop with a drag handle moves an item; a drop saves the whole list with every id exactly as stored, so legacy aliases are never rewritten to canonical ids and no section is added or removed.

### MCP Servers section

`SectionMcpServers` edits the whole `mcp_servers` map: list on the left, one `<button class="item">` per server with a state chip, editor on the right (a header with the server name followed by the server's only `Switch` (`shared/ui`, on = not `disabled`); then the tools block, name, command, args one per line, env rows, timeout, tool timeout rows). States come from `listMcpServers()` in `$lib/services/mcp.ts`, read once on mount, as do the tools from `listMcpTools()` (all tools of running servers, switched-off ones included). The chip is `serverChip(registry state or null, row.disabled)` (`$lib/utils/mcpServerChip.ts`):

| Registry state at start | Switch | Chip |
| --- | --- | --- |
| running | on | `running` |
| running | off | `stops after restart` |
| error | on | `error` |
| off or none | on | `starts after restart` |
| off, error or none | off | `off` |

A server the registry ran that is no longer configured shows `removed after restart`; a state `"off"` (skipped at start) is never listed as removed. The header switch sets `row.disabled` and writes at once with `tracker.flush(persist)`, as delete does.

Tools block of the editor: chip `off` shows "Off: tools are listed while the server runs." instead of it; a server that is on and failed to start shows its start error in full; a server the registry reports running lists its tools (`server === row.name`, switched-off ones included, "No tools." when none). Per tool: name, description, a `Switch` and a "Used by" line. The line has the tags `Chat` and `Settings agent` (from `toolUses(row.name, tool.name, store.settings.surfaces)`; the style of `ModelUseTags`; each tag is a button calling `navigateTo("surfaces.chat.generation.enabled_tools")` or `navigateTo("surfaces.settings_agent.generation.enabled_tools")`) or, when no surface lists the tool, "Used by nothing — assign in Chat ›" (a button navigating to the chat key); for a tool in `row.disabledTools` it reads "Off — not offered in Chat or Settings agent tools." instead of tags. The tool switch adds or removes the raw tool name in `row.disabledTools` and writes at once; `enabled_tools` entries of a switched-off tool stay, so switching it on restores them.

Rows are a local draft seeded on mount (`disabled` from `disabled ?? false`, `disabled_tools` from `disabled_tools ?? []`); every edit saves the whole map through `updateSetting("mcp_servers", map)`, `persist` carrying `disabled` and `disabled_tools` of every row so no edit strips them (text debounced via `useSaveTracker`, delete and the switches immediate; delete after an inline two-step confirm). Duplicate names are not saved and show an error at the name. Backend errors show at `mcp_servers.<name>` (name) and in `SettingField` for the catalog keys; `SettingField` gets no `itemId` there because its `itemId` match expects `[id]` keys and these are dotted. The section hint reads "Server changes apply after restart; tool switches apply at once."

Env rows have column headers ("Name in server", "Value"), shown when the server has at least one env row, and one row shape: name `TextInput`, a value cell, the remove button (`ActionIconButton` `X`, `variant="danger"`, label "Remove variable"). The value cell holds a `TextInput` (placeholder "value") for any value that is not a single `${NAME}` token, including an empty one or a mixed one such as `Bearer ${TOKEN}`; a single `${NAME}` shows as a `Chip` without `onclick` (a `<span>`, so the buttons inside are not nested in a button) with the name and, once the first env load finished, its state from `classifyReference` and the list: `NAME · set`, `NAME · missing` (listed without a value) or `NAME · not listed`. Inside the chip: "Add to list" only for `not listed` (`add_env_var`, secret on, then reload; a rejection shows under the row without its `row N: ` prefix and changes nothing) and an × button ("Clear value") that stores an empty value and brings back the text field. Typing a complete `${NAME}` into the text field turns it into the chip. The stored value stays the `${NAME}` string. The env list (`getEnvVars()`) loads on mount, on `onSettingsChanged` and on window `focus`; a failed load logs a warning and keeps the old list. Each value cell has an `InsertVariableButton` after the field or chip: with a text field it inserts `${NAME}` at the caret, with a chip there is no input, its `field` getter returns null and a pick replaces the value with `${NAME}`. The getter finds the row's input through a per-row wrapper (`valueCells[pair.key]`, `querySelector("input")`), as `command` does. Env names stay free text. The name input keeps a fixed 38 % (`.pair.env > .text-input`, the header's first column matches it): `TextInput` is `width: 100%`, so without that share it takes the whole row and the value cell collapses to 0 px, its field disappears and the following remove button is drawn over it.

`InsertVariableButton.svelte` (lucide `Braces`, next to `command` and `args`) opens a `FloatingPanel` with `MenuList` + `MenuItem` rows listing `getEnvVars()` (read on every open) in two labelled groups, Secrets first and Variables second, each sorted by name, a group without names omitted (`groupByKind` in `$lib/utils/envVarOptions`; the label is a non-clickable `div` styled in the component, not a `MenuItem`); a name without a value shows `missing` in the row's `shortcut` slot. Picking a name, when `field()` returns a field, inserts `${NAME}` at the caret or over the selection of its field through `insertAt()` (`$lib/utils/envVarOptions`), writes the new text into the field and to the bound row value through `oninsert`, then refocuses the field with the caret after the token. When `field()` returns null (an env row showing a chip), a pick only calls `oninsert` with `${NAME}`, which replaces the value. The caret and selection survive the blur caused by the click, so the button needs no focus tracking; in `args` the caret is on the line being edited. Escape closes the list and stops propagation. `field` is a getter because `TextInput` spreads extra props onto its `<input>` and exposes no element ref; `command` finds its input through the wrapper (`querySelector("input")`).

### Search and navigation

`SettingsSearch` (top of the sidebar) searches an entry's catalog label and description with `searchCatalog` in `$lib/utils/settingsSearch.ts` (see "Settings search"). Arrow keys move over the results and the last row, Enter or click on a result navigates and clears the query, Escape clears; its keydown handler stops propagation.

The results are a dropdown over the sidebar and the content: a `FloatingPanel` (`fitContent`, anchored to the input) holding a 300 px list, shown while the query is non-empty and the input is focused. Blur hides it and keeps the query; focusing again shows it. The list's `mousedown` is `preventDefault`ed, so a click on a row keeps the input focused. `FloatingPanel` is `position: fixed`, so the sidebar's `overflow: hidden` (`Sidebar.svelte`) and the `overflow-y: auto` of `.sidebar-inner` do not clip it; an absolutely positioned list wider than the 220 px sidebar would be cut there. Its rows are not `MenuItem`s: a result has two lines, the label (`--text-primary`) and "<section label> · <entry description>" (muted, one line with ellipsis; only the section label when the entry has no description); the highlighted row (also on hover) is `--surface-overlay`.

Every non-empty query ends with the row "Ask agent: <query>" (`Sparkles` in `--accent`, a `KbdHint` `Enter` while highlighted, `--accent-bg-soft` while highlighted, a `--border-faint` line above it), also after "No matching settings". It is part of the arrow-key cycle and is preselected when there is no result; otherwise the first result is. Choosing it clears the query and calls `openPanel("search-row")`, then `send(query)` when `agentHasUsableModel(surfaces, models)` (`$lib/utils/agentModel.ts`: the effective id of `agentModelId` is a `text` model of `models`) holds and the agent is not `running`, else `fillDraft(query)`: the query waits unsent in the composer.

#### Settings search

Query and texts are split into lowercase words (non-letter/non-digit separators). An entry matches a text when every query word matches some word of it. A query word `q` of n code points matches a word `w` exactly when `w.startsWith(q)`, or by typo when the Damerau-Levenshtein distance (optimal string alignment: insert, delete, substitute, adjacent transposition) between `q` and a prefix of `w` of length n−k … n+k (the whole `w` when shorter) is ≤ k. k = 0 for n < 4 (no typo match), 1 for 4 ≤ n ≤ 6, 2 for n ≥ 7. Four tiers, each entry in the first it reaches, catalog order within a tier, max 20 in total: exact in label, exact in label + description, typo in label, typo in label + description. The distance is own code in `settingsSearch.ts`: `fuzzyMatch` (`skillHighlight.ts`) is a subsequence match that accepts far too much, and a fuzzy-search library would be a new dependency for a catalog of a few hundred short texts.

`navigateTo(key)` of `getSettingsNavigation()` (`$lib/stores/settingsNavigation.svelte.ts`) is the single entry point for jumps, also for the settings agent's links. `key` is a catalog or concrete path (`models[<id>].api_key`, `mcp_servers.<name>.env`). It switches `activeSection` (owned by that store), sets `selectedItem` when the concrete path names a list item (`SectionModels` and `SectionMcpServers` select it), scrolls `setting-<catalog path>` into view and sets `highlighted` for 2000 ms; `SettingField` draws an accent outline while its catalog path matches. The key `models:new` switches to Models and sets the store's `createModelType` to `text`; `SectionModels` consumes it in an effect (sets its `creatingType`, calls `clearCreateModelType()`), so `CreateModelDialog` opens for a text model. A key `section:<id>` is a section link: a known id switches `activeSection`, scrolls every scrolled element inside `[data-settings-content]` (the `main` of `SettingsContent`) back to the top and sets `highlightedSection` for 2000 ms; `SettingsSection` draws the accent outline on its title `h2` and `SettingsSidebar` on the section's item while `highlightedSection` is the active section (`SectionModels` has no title, so only its sidebar item); an unknown id logs `warn` and changes nothing.

### Change history

`ChangeHistory` is a card at the bottom of `SectionHistory`: the settings agent's change-log entries of all hosts, newest first (`listChangeLog` in `$lib/services/changeLog.ts`). Each entry shows a title (`entryTitle` in `$lib/utils/changeLog.ts`: row labels for a card, `Secret <name>`, `Undo of <time of the undone entry>`), local time, host, kind, the request, and a state badge `applied` / `undone`. Expanding it shows each row's effects as before → after (file effects as a line diff) and test results; a secret effect (`set_env_value`) and a secret entry show only the variable name (`targetLabel` in `$lib/utils/changeLog.ts`, also used by `ProposalRow` and `conflictLines`, whose line for a secret conflict reads `<NAME>: changed since this entry`). Undo calls `undoChange(id, false)`: `conflicts` shows `UndoConflicts.svelte` (shared with `ProposalCard`), an inline list of targets with current vs expected value and "Undo anyway" (`force: true`); `skipped` shows "Secret backup is on <host>"; `undone` reloads the list. The list reloads on mount, on `change-log-changed` and on window focus.
